# DevExpress 서식 Tester 설계

이슈 #8의 설계 기준이다. 서식 담당자가 DB 없이 TXT 서식을 편집하고 Tester 화면에서 실제로 인쇄해 확인하는 도구다. 인쇄·위치·서식 처리는 [동기 USB MVP](SYNC_USB_MVP.md)와 [TXT 서식 편집 API](TXT_TEMPLATE_EDITOR.md)의 공개 API만 호출한다. 대안 비교는 [결정 기록](../design/decisions/2026-10-14-devexpress-tester.md)에 있다.

## 프로젝트와 빌드

`src/U2BIO.BT003PROLabelPrinting.Tester`에 WinExe 프로젝트 하나를 두고 솔루션에 넣는다.

| 항목 | 값 |
| --- | --- |
| 대상 | .NET Framework 4.6.1, C# 7.3, `PlatformTarget=$(Platform)`, `Prefer32Bit=false`, 경고를 오류로 처리 |
| 출력 | `bin\$(Platform)\$(Configuration)\`. x86/x64 이외의 플랫폼은 빌드 오류 |
| 제품 DLL | OfflineSmoke와 같은 `ProjectReference`(`Platform=AnyCPU`) |
| DevExpress | 20.2.6.0 GAC 참조, `Private=True`로 실행 폴더에 복사(phase2와 같음). `Properties\licenses.licx`를 포함 |
| SDK native | `..\U2BIO.BT003PROLabelPrinting\Sdk\$(Platform)\`의 두 파일을 `None` 링크로 실행 폴더에 복사한다. 결과는 [SDK 배포](../SDK_DEPLOYMENT.ko.md)의 실행 폴더 구성(같은 비트수 한 쌍)과 같다. `Bt003NativePlatform`이 지정됐는데 Platform과 다르면 빌드 오류로 막는다. |
| 솔루션 | x86→x86, x64→x64, Any CPU→x86. 빌드 설정 메시지 `BUILD_SETTINGS|...`를 다른 프로젝트와 같은 형식으로 출력 |

verify-build는 기존 검사를 그대로 두고 플랫폼마다 다음을 추가한다.
- Tester의 빌드 설정 메시지를 확인한다.
- `--self-check --expect-<platform>`을 실행한다.
- 실행 폴더의 SDK 두 파일이 고정 해시와 같은지 확인한다.
- 실행 폴더의 관리 DLL이 검증한 제품 DLL과 같은지 확인한다.

이 빌드에는 DevExpress 20.2.6이 설치된 개발 PC가 필요하다.

## 파일 구성

| 파일 | 책임 |
| --- | --- |
| Program.cs | `--self-check`이면 화면 초기화 전에 SelfCheck로 분기한다. 아니면 phase2 Checkup 순서로 초기화한다: 스킨 등록, 예외 처리, 스킨 VS2010, 기본 글꼴 굴림 9pt. |
| FrmMain(.Designer).cs | 편집·미리보기·연결·인쇄 화면. Bt003Printer 하나와 TemplateDocument 하나를 가진다. |
| FrmSettings(.Designer).cs | phase2 환경설정 모양의 설정 화면 |
| TesterSettings.cs | 설정 값과 XML 읽기·쓰기. 파일 경로는 인수로 받는다. |
| UsbPrinterList.cs | Windows USB 프린터 드라이버(usbprint) 장치 목록을 읽어 포트 번호와 장치 이름을 만든다. SDK를 쓰지 않는다. |
| TemplateDocument.cs | 열린 서식의 상태(현재 BtplTemplate, 경로, 수정 여부, 마지막 열기·저장 시각)와 저장 규칙. 미리보기용 변수 치환, 블랙마크 칸 표시 매핑, 잉크 영역 판정 함수도 둔다. |
| SdkTextRenderer.cs | SDK AW와 같은 GDI 조건으로 문구를 1bpp 그림으로 그리고 잉크 범위를 구한다. SDK 글꼴 설정을 읽기만 한다. |
| SelfCheck.cs | 장치 없는 검사 |

화면 파일은 Visual Studio 디자이너로 열 수 있는 Designer 형식으로 만든다. 화면 밖에서 검사해야 하는 규칙은 TesterSettings, TemplateDocument, UsbPrinterList, SdkTextRenderer에만 둔다.

## 설정

- 위치: `Environment.SpecialFolder.LocalApplicationData` 아래 `U2BIO\BT003Tester\settings.xml` 하나. x86/x64가 같이 쓴다.
- 형식: XDocument로 쓴 버전 1 XML이다.

```xml
<TesterSettings version="1">
  <Port>0</Port>
  <PresentationDistanceMm>15</PresentationDistanceMm>
  <TemplateFolder></TemplateFolder>
  <RecentFiles><File>…</File></RecentFiles>
  <Dpi>300</Dpi>
  <SensorOffsetMm>1.5</SensorOffsetMm>
  <VerticalOffsetMm>3.6</VerticalOffsetMm>
  <HorizontalOffsetMm>-1</HorizontalOffsetMm>
  <LabelMediaMode>BlackMark</LabelMediaMode>
</TesterSettings>
```

| 항목 | 기본값 | 검사 |
| --- | --- | --- |
| Port | `0`(운영 USB 포트) | 빈 값과 제어문자 거부 |
| PresentationDistanceMm | 15 | 정수 0~1000 |
| TemplateFolder | 빈 값 | 빈 값이거나 있는 폴더 |
| RecentFiles | 없음 | 최대 10개. 대소문자를 무시해 중복을 없애고 최근 것이 앞에 온다. |
| Dpi | 300 | 203 또는 300 |
| SensorOffsetMm | 1.5 | −1000~1000, 소수 셋째 자리까지 |
| VerticalOffsetMm | 3.6 | 0~1000, 소수 셋째 자리까지(음수면 DLL이 항상 거부) |
| HorizontalOffsetMm | −1.0 | −1000~1000, 소수 셋째 자리까지 |
| LabelMediaMode | BlackMark | BlackMark 또는 Gap. 프린터에 넣어 둔 용지 방식이며 프린터에서 조회하지 않는다. |

dpi와 세 보정은 이 프린터에서 잰 장치 값이고 용지 방식은 장치에 넣은 용지라 서식이 아니라 설정에 둔다.

**읽기**
- 파일이 없으면 기본값으로 만든다.
- 프린터 보정·용지 방식 항목이 없는 이전 파일은 그 항목만 기본값으로 읽고, 읽기만 해서는 다시 쓰지 않는다. 최근 파일 추가 같은 통상 저장 때 새 항목도 함께 쓴다. 값이 있는데 잘못되면 손상으로 본다.
- 읽을 수 없거나 값이 잘못됐으면 경고하고 기본값으로 시작한다. 이때 사용자가 설정 화면에서 확인을 누르기 전까지 기존 파일을 덮어쓰지 않는다. 그동안 최근 파일 목록은 메모리에서만 갱신하고, 확인을 누를 때 함께 저장한다.

**쓰기**
- 같은 폴더의 임시 파일에 먼저 쓴 뒤 교체한다.
- 연결 중에 설정을 바꾸면 다음 연결부터 적용된다. 상태 줄에는 연결할 때 쓴 값을 표시한다.

## 서식 상태와 저장

TemplateDocument는 화면과 독립된 규칙을 가진다.
- **편집**: `Apply(편집 함수)`가 성공하면 결과 객체를 채택한다. DLL 예외가 나면 이전 객체를 그대로 둔다.
- **수정 여부**: 마지막으로 열거나 저장한 `ToBtpl()` 원문과 지금 원문이 다르면 수정됨이다. 표준 숫자 표기의 값을 바꿨다가 되돌리면 원문이 같아져 수정됨이 아니다. 선행 0 같은 비표준 표기는 DLL이 바뀐 칸을 표준 표기로 쓰므로 값만 되돌려도 수정됨으로 남는다. 저장 실패는 비교 기준을 바꾸지 않는다.
- **Save·SaveAs**: 성공하면 반환 객체를 채택하고 경로·수정 여부·시각을 갱신한다. 실패하면 상태를 바꾸지 않는다. 같은 경로를 SaveAs 대상으로 고르면 DLL의 SameSavePath를 받아 Save를 안내한다. 덮어쓰기는 화면이 확인을 받은 경우에만 `overwrite: true`로 호출한다.
- **SourceChanged**: 다시 읽기, 다른 이름 저장, 편집 유지 중 하나를 고르게 한다. 원본이 삭제된 경우는 다시 읽기를 제외한다.
- **버리기 전 확인**: 열기, 최근 파일 열기, 닫기, 종료 전에 수정됨이면 저장/저장 안 함/취소를 묻는다. 저장이 실패하거나(SourceChanged 포함) 취소되면 전환이나 종료를 하지 않는다. 세 경우 모두 같은 함수 하나로 처리한다. SourceChanged 다시 읽기는 같은 경로 저장이 항상 다시 충돌하므로 "편집 버리고 다시 읽기/취소"만 묻는다.
- **닫기**: 서식을 내려놓고 처음 실행한 상태로 돌아간다. 블랙마크 칸은 운영 기준값으로 되돌리고, 가변데이터는 편집기 세션 값이라 그대로 둔다.
- **되돌리기 기록**: 편집이 원문을 바꿀 때마다 이전 원문을 기록한다(최대 100단계, 원문이 같은 편집은 기록하지 않음). 되돌리기·다시 실행·마지막 저장 상태로·처음 연 상태로는 모두 현재 객체의 DLL `WithRawText`로 원문을 되살려, 현재 경로·인코딩·저장 기준 해시를 유지한다(저장 뒤 되돌려도 다음 저장이 SourceChanged로 잘못 막히지 않는다). 마지막 저장 상태로·처음 연 상태로도 한 단계로 기록된다. 처음 연 상태는 이번 실행에서 성공적으로 열거나 다시 읽은 원문이며 저장해도 바뀌지 않는다. 열기·다시 읽기·닫기는 기록을 비우고, 저장·다른 이름 저장은 유지한다. 수정 여부는 되돌린 뒤에도 원문 비교로 정한다. DLL이 원문을 거부하면(두 인수 `^Q`, AW X 0 이하 등) 공통 오류 줄에 이유를 남기고 상태·기록은 그대로 둔다. 라벨 치수·보정·가변데이터는 서식 원문이 아니라 기록 대상이 아니다.
- **편집기 확정**: 열기·최근 파일 열기·닫기·종료·저장·다른 이름 저장·두 인쇄·되돌리기 전에 문구·용지·인쇄 그리드의 편집기를 닫아 값을 확정한다. 값이 거부돼 편집기가 남으면 그 동작을 멈춘다.
- **열린 서식이 없을 때**: 경로 줄은 "열린 서식 없음"을 표시하고 편집·인쇄 버튼을 막는다. 새 서식 만들기 기능은 없다. 기존 TXT를 열어 다른 이름으로 저장해 만든다.
- **경로가 없는 서식**: `FilePath`가 null이면 경로 칸에 "저장 안 됨"을 표시한다. 현재 버전은 `Load`로만 열기 때문에 이 상태가 생기지 않는다.

## 메인 화면

LayoutControl 하나가 창 전체를 채운다. 왼쪽 열(4·5)과 오른쪽 탭(6) 사이에 끌 수 있는 구분선(SplitterItem)을 두며, 처음 비율은 760:511이다. 열 너비는 글자 길이로 바뀌지 않는다.

1. **도구 모음**: 열기(DropDownButton + DXPopupMenu로 최근 파일 전체 경로), 저장, 다른 이름 저장, 닫기, 되돌리기(DropDownButton: 누르면 한 단계 되돌리기, 메뉴는 다시 실행 Ctrl+Y·마지막 저장 상태로·처음 연 상태로) / 연결, 해제, 상태 / 위치 확인, FEED+확인("#19 실기 확인 전" 표시) / 설정
2. **현재 파일 줄**: 읽기 전용 TextEdit(전체 경로, 툴팁), 수정 표시, 마지막 열기·저장 시각. 창 제목에는 `파일 이름 *`를 표시한다.
3. **공통 오류 줄**: 입력 칸에 속하지 않는 오류를 표시하는 LabelControl 하나다.
   - 대상: 열기·편집·저장·인쇄 준비에서 나는 BtplFormatException과 IO 오류
   - 표시 내용: `Code`, `TemplateLine`(있을 때), 메시지
   - 추가 안내: `AmbiguousFrame`·`AmbiguousSetting`·`LockedTextArguments`이면 "외부 편집기에서 고친 뒤 다시 여세요"라고 붙인다.
   - 셀 입력 오류는 이 줄이 아니라 해당 칸의 `e.ErrorText`에 표시한다.
4. **왼쪽: 참고 미리보기**
   - 표시 기준: 블랙마크 칸과 설정의 dpi·보정으로 구한 LabelArea(실선)와 SafeArea(점선), TextElements의 문구. 범례는 "계산 입력 기준"과 글꼴(요청한 이름, GDI가 실제로 고른 이름이 다르면 "대체됨")을 적어 TXT에서 실측값을 복원한 것처럼 보이지 않게 한다. 계산 입력이 잘못됐으면 영역을 그리지 않는다.
   - 문구 그림(SdkTextRenderer): SDK(x64 정적 분석)와 같은 조건으로 그린다. 글꼴은 SDK 설정 `HKCU\Software\BitekTechnology\AXBT003\FontName`(없으면 SDK 기본 돋움체), LOGFONT 높이 `+size * 340 / 72`(셀 높이), 굵기 0·1=400, 2=600, 3=700, DEFAULT_CHARSET, FF_ROMAN|VARIABLE_PITCH, CP949 엄격 변환 바이트로 `TextOutA`(0,0) 기본 정렬(TA_TOP), 폭 32픽셀 배수, 1bpp. 미리보기는 그 그림을 배율로 줄여 그린다.
   - 한도: 그림 하나는 한 변 8000 dot·1600만 픽셀 이하. 갱신 때 이번 서식에 쓰지 않는 그림을 먼저 놓고, 남은 그림과 새로 만들 그림(만드는 동안 비트 배열과 표시용 그림 두 벌)을 합쳐 32 MB 이하로 만든다. GDI 그림은 표시용 그림을 만들기 전에 놓는다. 넘거나 CP949로 바꿀 수 없거나 GDI 호출이 실패한 줄은 그리지 않고 "판정 불가"로 표시한다(빨간 점선 셀 상자).
   - 잉크 판정: 그림의 실제 잉크 범위(반열림)를 서식 좌표로 옮겨 LabelArea 밖이면 빨간색 "라벨 밖(잘림)", LabelArea 안이지만 SafeArea 밖이면 주황색 "안전 영역 밖"으로 그린다. 빈 문구·공백은 잉크가 없어 판정하지 않는다. 정렬·회전 문구는 판정에서 빼고 회전 없이 그린다. 서식의 `FONT,` 지정과 SDK 자동 줄바꿈은 반영하지 않는다. 인쇄는 막지 않는다. 다른 PC 글꼴과 물리 잉크 번짐은 보장하지 않는다.
   - 경고 줄: 미리보기 아래 고정 너비 줄에 "미지원 줄: 번호"(없으면 "없음"), "라벨 밖(잘림): 줄 11(아래 21 dot)", "안전 영역 밖: 줄 12(아래 5 dot)", "판정 불가: 줄 n(이유)", "판정 제외(정렬·회전): 줄 번호"를 ` · `로 이어 표시한다. 계산 입력이 잘못됐으면 "계산 입력 오류로 영역 판정 안 함"을 쓴다. 미지원 줄·잘림·판정 불가가 있으면 빨간색, 안전 영역 밖만 있으면 주황색, 아니면 회색이다. 넘치는 글자는 `…`로 줄이고 툴팁에 전체를 보인다. 공통 오류 줄은 편집마다 지워지므로 이 경고를 두지 않는다.
   - 좌표 눈금: 캔버스 왼쪽 위가 서식 원점(0,0)이다. 왼쪽에 Y 눈금(10 dot 짧은 선, 40 dot부터 숫자), 위쪽에 X 눈금(50 dot 짧은 선, 100 dot부터 숫자)을 그린다. 숫자 간격은 화면에서 숫자 높이·폭보다 넓어질 때까지 두 배씩 늘리고(TemplateDocument.RulerStep), 짧은 선은 3 px 이상일 때만 그린다.
   - 경계값: 현재 LabelArea·SafeArea의 위·아래 끝 값(반열림 끝 좌표, 운영 기준 43·66·255·279)을 캔버스 오른쪽 바깥에 선 색으로 적고 원래 Y에서 짧은 선으로 잇는다. 숫자는 설명 줄 위까지 겹치지 않게 쌓고, 아래 끝을 넘으면 위로 되돌리며, 네 줄을 담을 높이가 없으면 생략한다(TemplateDocument.StackLabels). 캔버스(받침지 폭) 안의 범례·영역·문구·선택 표시는 캔버스 안으로 잘라 그려 눈금·경계값과 겹치지 않게 한다. 캔버스 밖으로 나간 사실은 경고 줄과 선택 줄 설명에 남는다.

- 모든 장치 호출은 `async`/`await Task.Run`으로 실행한다(제조사 샘플도 작업 스레드에서 인쇄한다). 예외로 창을 닫을 때의 연결 해제(Disconnect·Dispose)는 진행 중 작업이 끝난 뒤 UI 스레드에서 동기로 실행한다. SDK 응답이 늦으면 닫는 동안 창이 잠시 멈출 수 있다.

- 수정됨 상태이면 저장할지 묻는다. 저장이 실패하거나 취소되면 종료를 중단한다.

## 장치 없는 검사

`--self-check --expect-x86|x64`는 화면과 SDK 없이 다음을 확인하고 종료 코드로 결과를 알린다(성공 0, 실패 1, 잘못된 인수 2).

1. 프로세스 비트수가 기대값과 같다.
2. 설정: 없는 파일은 기본값으로 생성한다. 값을 바꿔 저장한 뒤 다시 읽으면 같은 값이다(프린터 보정 포함). 잘못된 값(빈 포트, 1001 mm, dpi 200, 세로 보정 음수, 소수 넷째 자리)은 거부한다. 손상된 파일과 잘못된 보정 값이 있는 파일은 기본값으로 시작하고 원본을 바꾸지 않는다. 보정 항목이 없는 이전 파일은 읽기만 하면 원본이 그대로이고, 최근 파일을 더하면 보정 기본값과 함께 저장된다. 용지 방식은 Gap 저장·다시 읽기, Unspecified·Ambiguous 거부, 없는 이전 파일은 BlackMark, 잘못된 값은 손상을 확인한다.
3. 서식: 합성 CP949 TXT를 열어 편집하면 수정됨이 된다. Save 뒤 파일과 `ToBtpl()`이 같고, 연속 Save도 된다. SaveAs 뒤 다음 Save는 새 경로에만 쓰고 원래 파일은 바뀌지 않는다.
4. 실패 보존: 외부에서 파일을 바꾼 뒤 Save하면 SourceChanged가 나고, 편집본·수정 표시·외부 내용이 그대로다. 기존 다른 파일로 SaveAs(덮어쓰기 거절)하면 그 파일과 편집본이 그대로다. 손상된 설정으로 시작한 뒤 최근 파일을 갱신해도 원본 설정 파일이 바뀌지 않는다.
5. 서식 화면: 미리보기 치환은 DLL `GetPreviewText`를 쓰므로 Validation 검사가 확인한다.
   - 수정 여부: AW Y와 `^Q`를 바꿨다가 되돌리면 수정됨이 아니고, 선행 0 표기는 수정됨으로 남는다. 저장 실패 뒤 되돌려도 수정됨이 아니다.

   - 잉크 판정: 운영 기준 용지와 로컬 잉크 [6,40)에서 Y215/216(안전 영역), Y239/240(라벨)의 안·밖과 1 dot 초과, Y260 잘림 21 dot, 위·왼쪽·오른쪽 거리, 빈 잉크·판정 불가, 정렬 줄 제외와 목록 분리를 확인한다.
   - 그림 생성기: 영문·한글 혼합 문자열의 1bpp 그림과 잉크, 빈 문자열·공백, CP949 변환 불가, 크기 한도, 메모리 예산, 굵기 매핑, 실현 글꼴 이름과 없는 글꼴의 대체, 200회 반복 뒤 GDI 객체 수가 2개 넘게 늘지 않음을 확인한다(글꼴에 따라 달라지는 잉크 수치는 검사하지 않는다).
   - 인쇄 전 검사: 세 인수 `^Q`는 블랙마크 설정에서 확인 없이 통과하고 간격 설정에서는 확인을 받는다. 두 인수 `^Q`는 그 반대이며 확인 문구에 `^Q` 줄 번호가 있다. `^Q` 없음·앞 공백·네 인수(CRLF·LF·CR)는 어느 설정이든 확인을 받는다. 해석된·해석하지 못한 AW X 0은 간격 서식이어도 줄 번호와 함께 막는다. 저장된 파일은 다시 읽기부터 인쇄 호출까지 파일 쓰기가 막히고, 확인한 원문과 다르면 인쇄하지 않으며, 끝나면 잠금이 풀린다.
6. USB 목록: 합성 목록으로 번호·이름 정리, 빈 번호 건너뛰기, 저장 포트의 감지 안 됨 표시, 감지 대수 안내를 확인한다. 실제 레지스트리는 읽지 않는다.
7. 실행 폴더에 SDK 두 파일이 있지만 프로세스에 로드되지 않았고, 화면을 만들지 않았다.

임시 폴더만 쓰며 실제 사용자 설정과 운영 서식은 건드리지 않는다. 화면 배치, F12/ESC, 오류 표시, 저장 확인은 장치 없이 실제 화면에서 따로 확인한다. 물리 출력은 사용자 승인과 직접 관측으로만 확인한다.
