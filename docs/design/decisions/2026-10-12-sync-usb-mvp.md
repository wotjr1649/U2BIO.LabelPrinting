# 동기 SDK 호출과 두 파일 구조

## 결정

사용자는 Grilling에서 원본 StringBuilder, 배포 시 해시 검사, DllImport 기본 로딩, 기본 파일 읽기 잠금, 새 동기 USB API, 작은 결과, SDK 서식 해석을 선택했다. 기존 고급 API와 예제 이행을 허용했고 한글 주석·사람이 이해할 수 있는 코드를 요구했다.

## 대안

기존 네 파일을 두 개에 합치면 1,147줄의 worker·시간 제한·일괄·결과 체계가 대부분 남는다. 원본 API 사용과 유지보수 목표에 맞지 않아 채택하지 않는다. 새 API는 장치 동작을 제조사 선언으로 전달하고 우리 책임을 입력·순서·실패·결과·정리에 한정한다.

## 영향

기존 API 호환성이 깨진다. 새 구조는 기존 출력·DLL·부모 경로 보호와 동등하지 않다. 호출 프로그램은 UI 실행과 새 결과 해석을 맡는다. 실제 SDK/장치와 외부 호출 프로그램의 이행은 별도 확인 대상이다. 판단 근거와 동작은 SYNC_USB_MVP.md에 모은다.
