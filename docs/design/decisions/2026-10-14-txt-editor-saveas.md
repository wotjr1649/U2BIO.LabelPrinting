# TXT 편집 모델 축소와 명시적인 저장

2026-10-14 사용자 grilling 결정. 이슈 #16. [제품 계약](../../specs/TXT_TEMPLATE_EDITOR.md)이 API와 저장 동작의 기준이다.

TXT 인쇄만 제공하는 경우 Templates 전체 제거가 가능했으나, 사용자가 좌표·문구 편집과 참고 미리보기, AW 추가, 원본을 남기는 다른 이름 저장을 유지하도록 확정했다. 따라서 원문 기반의 작은 편집 모델을 동일 DLL에 남긴다. 선택 기능은 기본 SDK 인쇄 경로와 독립이다.

| 대안 | 변경과 비용 | 판단 |
| --- | --- | --- |
| Templates 전체 제거 | DLL이 가장 작지만 편집/미리보기용 모델을 호출부에서 다시 만들어야 함 | 확정한 기능을 충족하지 못함 |
| 기존 전체 모델 유지/파일 병합 | JSON/XML·DataTable·렌더 결과와 기존 구문 제한이 남음 | TXT 중심 범위와 읽기 쉬운 코드 목표에 맞지 않음 |
| 원문 + AW/Q/W/S/H 추출 모델 | 두 파일로 원문 보존·부분 편집·저장 제공, 화면 책임은 호출부 | 채택 |

초기 right pane 설계 검토는 원문/줄끝, frame, WithRawText의 파일 기준, SaveAs 덮어쓰기 경합과 저장 확정 순서의 보완을 요구했다. 이를 구체 계약으로 정한 재검토는 READY다. 파일 존재 확인만으로 기본 덮어쓰기를 막지 않고 File.Move를 사용하며, 저장 후 파싱 대신 반환 객체를 먼저 준비한다.

AW Size/Weight만 전용 편집 범위를 넓히고 Alignment/Rotation은 원문으로 유지한다. Size 단위와 전체 SDK 지원을 추정하지 않는다. 여러 frame도 원문으로 보존하지만 모호한 추가/설정 대상은 자동 선택하지 않는다. 새 계층·frame UI·SDK 해석기·실제 글꼴 렌더러를 추가하지 않는다.

Save와 SaveAs를 구분하고 성공한 반환 객체만 새 편집 파일의 기준으로 채택한다. 실패·취소의 편집 내용은 호출 프로그램이 유지한다. JSON/XML·데이터 바인딩·일괄 렌더 API 호환 제거와 호출부 재빌드는 승인된 범위다. Wrapper·PrinterModels·Bt003Printer·장치 미실행 경계는 유지한다.
