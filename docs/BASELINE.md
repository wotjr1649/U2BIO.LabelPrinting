## 참고 자료와 기준의 경계

- BTPL_API_GUIDE.ko.md는 일반 언어 참고 자료다. 내용의 SHA-256은 `6700c7b53292832302257860963be8aaa58a0f1ac39a7cf67757610c6e967ca7`이며 DESIGN 10절에서 대조한 범위만 구현 근거로 사용한다.
- 제조사 문서·SDK 샘플·DLL은 원본 상태로 보존한다. 이 기준 커밋은 자체 작성 개요·설계·API 대조·작업 계획·본서만 포함하며 참고 자료 전체를 포함하지 않는다.
- native 기준 네 파일의 해시는 SDK_API_COVERAGE 2절에서 관리한다. 같은 버전 번호만으로 다른 파일을 혼용하지 않는다.
- 사용자가 확정한 정책은 DESIGN 1절, 구현 선택은 관련 계약과 11절, 장치 미확정 사실은 8절을 따른다.

## 변경 관리

1. 이 태그를 이동하거나 기존 기준 커밋을 수정하지 않는다. 후속 문서 변경은 새 커밋과 관련 이슈로 추적한다.
2. 사용자 정책을 바꾸는 변경은 별도 결정으로 기록한다. 장치 계약 확인은 시험 근거와 확인된 범위를 문서에 추가한다.
3. API 변경 시 관련 호출 예시·결과 모델·인수 사례·작업 완료 조건을 함께 갱신한다.
4. 이슈를 닫을 때 구현 커밋과 실제 검증 증거를 기록한다. 미실행·미확인 조건은 통과로 기록하지 않는다.

## 현재 미완료 상태

솔루션·DLL·Tester는 아직 구현하지 않았다. USB 인쇄 전용 ABI·응답·수량·글꼴·RFID 보존 실기 검증은 남아 있다. TASK-01의 문서 부분만 확정하며 프로젝트 구성 및 나머지 개발 작업은 완료 조건을 충족해야 한다.
