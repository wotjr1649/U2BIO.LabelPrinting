## 공통 완료 규칙

- DLL 우선: `U2BIO.BT003PROLabelPrinting`, .NET Framework 4.6.1. UI는 `U2BIO.BT003PROLabelPrinting.Tester`, WinForms와 DevExpress 20.2.6.
- 기존 RFID 값 보존, 1차 텍스트만 지원. RFID API는 외부 공개 및 인쇄 흐름 호출 금지.
- BTPL이 서식 기준. JSON은 매핑·출력 형식·nullText만 저장한다. DB 조회는 호출 프로그램의 책임이다.
- 텍스트 넘침·DPI 설정·자동 줄바꿈·자동 재출력·대기열을 추가하지 않는다.
- 각 이슈를 닫을 때 구현 커밋, 실행한 검사·결과, 미검증 항목을 기록한다. 실제 장치 증거가 필요한 조건은 fake SDK 성공으로 대체하지 않는다.
- 인쇄 데이터·기존 RFID 실제 값·인증 정보는 GitHub 시험 기록에 넣지 않는다. 합성 데이터와 값 일치 여부로 증거를 남긴다.

## TASK-01: 설계 기준 버전 확정 및 개발 프로젝트 구성

목적: 확정 설계를 추적 가능한 기준으로 만들고 DLL부터 구현할 수 있는 최소 빌드 구성을 만든다.

범위: 기준 문서·작업 등록, 솔루션, 공통 DLL과 UI 없는 최소 검증 프로젝트. 제조사 DLL의 전역 설치나 제품 UI 구현은 포함하지 않는다.

완료 조건:

- [x] 설계 기준을 v0.1.1-design으로 지정하고 대상 문서·참고 자료 해시·변경 규칙을 기록한다.
- [x] TASK-01~TASK-09 GitHub 이슈와 선행 관계를 등록하고 로컬 문서에 대응표를 남긴다.
- [x] .NET Framework 4.6.1의 공통 DLL과 최소 검증 프로젝트를 생성하고 실제 빌드가 성공한다.
- [x] DLL은 DevExpress 및 DB 연결 구성 없이 참조할 수 있고 관리 코드는 AnyCPU로 빌드한다.
- [x] 검증 실행 파일은 x86/x64를 명시하고 출력 폴더를 분리한다. Prefer32Bit=false를 확인한다.
- [x] 실행한 빌드 명령, 산출물 경로와 기준 커밋을 기록한다.

근거: DESIGN 1·5·7절. 실제 빌드·실행 증거는 [BUILD_EVIDENCE.md](BUILD_EVIDENCE.md)에 기록한다. 로컬 완료와 원격 이슈 종료·통합 상태는 구분한다.

## TASK-02: Native SDK 래핑과 USB 인쇄 계약 검증

목적: 인쇄 전용 SDK 호출의 원형과 실제 동작을 먼저 확인하여 이후 구현에서 성공 판정과 RFID 보존을 추정하지 않게 한다.

범위: 내부 native 로더·delegate 선언·USB 진단 코드·제조사 및 실기 증거. 진단 코드는 생산 PrintContractUnverified 게이트를 우회하는 공개 API로 만들지 않는다.

완료 조건:

- [ ] SDK_API_COVERAGE의 원형 확인 대상 41개를 내부 래핑한다. StartPrintWithRfid2와 없는 ReadResponseMessage 원형은 추정하지 않는다.
- [ ] 기준 BlackfishNfcLib.dll·HFModule.dll 쌍에 대해 아키텍처·해시·로드 충돌·export를 검사하고 절대경로의 제한된 검색 로더를 구현한다.
- [ ] 문자열 ANSI 전달, 입출력 방향, StdCall, 반환 버퍼의 바이트 상한·종료 규칙을 제조사 계약 및 x86/x64 증거로 확인한다.
- [ ] USB 식별 문자열과 RFID 포트 없는 연결·해제를 실제 장치로 확인한다.
- [ ] StartLabelPrint의 인수·전용 응답 형식·완료 의미와 오류 판정을 확인한다. SendData 성공이나 RFID 응답 형식으로 대체하지 않는다.
- [ ] 합성 문구의 한글과 사용할 BTPL 글꼴·인수 조합, 한 행 한 장, RFID 값 전후 일치를 실제로 확인한다.
- [ ] 장치·펌웨어·DLL 해시·시험 일시·결과와 미확인 항목을 기록한다. 안전한 버퍼 계약 등 핵심 미확정 상태에서는 완료 처리하지 않는다.

근거: DESIGN 5·8절, SDK_API_COVERAGE. C20·C21. 장치 준비 대기 중 TASK-03~TASK-04 진행 가능.

## TASK-03: BTPL 서식 해석·편집·저장 구현

목적: 업무별 요소 수나 위치를 고정하지 않고 BTPL을 안전하게 편집·저장한다.

완료 조건:

- [ ] 명령별 문법·허용 목록·단일 프레임을 검사하고 오류 위치를 반환한다. RFID 및 미지원 명령은 오류이며 자동 삭제하지 않는다.
- [ ] 필수 Q/W/S/H, 중복과 명령 위치를 검사하고 선택 기본값 P1/C1/R0/E0/D0/O0를 계약대로 한 번씩 생성한다.
- [ ] 텍스트 추가·삭제·복사·수치 변경과 원문 인수를 보존한다. AW의 미확정 네 인수는 잠근다.
- [ ] ExpandFixedLines로 고정 줄바꿈을 실제 명령에 저장하고 요소 인덱스·줄 배치 옵션을 재매핑하며 변수 표식은 보존한다.
- [ ] 인코딩·외부 파일 변경·I/O 오류를 표시하고 임시 파일 준비 후 원자적 파일 교체를 사용한다. 파일 쌍 전체의 원자성을 주장하지 않는다.
- [ ] Save 반환 객체로 연속 저장할 수 있고 자기 저장을 외부 변경으로 오판하지 않는다.
- [ ] 프린터·native DLL 없이 C17/C18/C22/C23/C24의 관리 코드 조건을 실행하여 결과를 기록한다.

근거: DESIGN 2·6·11절. 넘침 검사·DPI 변환·자동 줄바꿈은 추가하지 않는다.

## TASK-04: JSON 바인딩·DataTable 렌더링·관리 사전검사 구현

목적: 호출자가 전달한 데이터를 템플릿 하나에 바인딩하고 장치 없이 내용을 검사·미리보기 준비한다.

완료 조건:

- [ ] JSON은 변수-컬럼 매핑, 선택 출력 형식, nullText만 관리하며 위치·글꼴·DPI를 넣지 않는다.
- [ ] DataTable/DataRow 입력을 계약대로 스냅샷하고 컬럼명·자료형·형식을 검사한다. 원본 변경이 요청에 영향을 주지 않는다.
- [ ] NULL/DBNull/빈 문자열/공백에는 문자열 nullText를 적용한다. 누락/null 설정은 오류, 명시적 빈 nullText는 정상이며 컬럼 누락은 별도 오류다.
- [ ] 반복·순서가 다른 변수와 쉼표/공백/!!를 보존하고 고정·변수·대체 문구의 예약 문자 및 제어 문자를 동일하게 검사한다.
- [ ] 가변 줄바꿈은 명시적 LineAdvance를 적용하고 필요한 옵션이 없으면 MissingLineAdvance다. 옵션을 JSON에 저장하지 않는다.
- [ ] BtplProcessor.Validate/Render는 native DLL 없이 동작한다. 관리 오류, 부분 참고 미리보기, 미확인 장치 지원과 인쇄 가능 여부를 구분한다.
- [ ] 모든 행의 관리 검사 결과를 입력 순서대로 제공하고 C01/C02/C19의 오프라인 조건 및 정상·오류 바인딩 검사를 실행한다.

근거: DESIGN 2·3·11절. C01의 실제 장치 출력 차단은 TASK-05에서 완성한다.

## TASK-05: 연결 수명·장치 사전검사·단건 인쇄 구현

목적: 연결부터 해제까지 소유권을 유지하고 검증된 인쇄 전용 경로로 한 건을 출력한다.

완료 조건:

- [ ] USB 우선 연결과 TCP/IP·RS-232의 공개 연결 옵션·API 및 내부 SDK 경로를 구현한다. 미검증 transport를 실기 성공으로 표시하지 않는다.
- [ ] 연결 상태·프로세스 SDK 점유·대상 장치 mutex와 소유권을 구현하고 Busy 요청을 대기열 없이 거절한다.
- [ ] ValidateForPrint는 관리 검사 뒤 장치 검사를 수행하고 ResetForm·서식 등록·인쇄를 호출하지 않는다. Port Open을 용지·리본·헤드 준비로 해석하지 않는다.
- [ ] 미검증 ABI·글꼴·명령 조합은 PrintContractUnverified 또는 DeviceSupportUnverified로 차단한다.
- [ ] Print는 매번 사전검사를 하고 ResetForm→서식 등록→StartLabelPrint→전용 응답 판정 순서로 진행한다. RFID 함수는 호출하지 않는다.
- [ ] 실행 단계·PrintInvoked·함수별 raw 코드·정리 결과를 반환하고 연결 실패/부분 연결/해제 미확인/Dispose 뒤 상태를 계약대로 처리한다.
- [ ] C01/C05/C14/C15/C16 및 USB 단건 정상·오류를 검증하고 TCP/IP·RS-232의 API 검사와 실기 여부를 각각 기록한다.

근거: DESIGN 3~5·11절. 단건 성공은 TASK-02의 실제 응답 계약을 근거로 판단한다.

## TASK-06: 일괄 인쇄·취소·시간 제한·실패 결과 구현

목적: 여러 행을 출력할 때 부분 성공·실패·결과 불명과 미시도를 정확하게 구분한다.

완료 조건:

- [ ] 템플릿 하나와 여러 데이터 행을 입력 순서대로 처리하며, 전체 행 사전검사 중 오류가 하나라도 있으면 전체 인쇄를 시작하지 않는다.
- [ ] 실행 중 Failed/Unknown이면 즉시 중단하고 남은 행은 NotAttempted다. 자동 재시도·재출력은 없다.
- [ ] 사전 취소·Busy·미완료 검사에 nullable 결과를 적용하고 건별 결과·집계·StopReason의 일관성을 검사한다.
- [ ] SDK 호출 전후와 최종 인쇄 직전에 취소·Dispose·종료 상태를 확인한다. 현재 native 호출은 강제 중단하지 않는다.
- [ ] 기본 호출 제한 30초와 허용 설정 범위를 적용한다. 인쇄 호출 전 timeout은 Failed, 인쇄 진입 후 결과 미확인은 Unknown으로 구분한다.
- [ ] 늦은 서식 등록이 성공해도 새 인쇄를 시작하지 않는다. 반환한 결과는 변경하지 않고 pending·늦은 정리는 상태 조회로 확인한다.
- [ ] C02~C13/C16을 실행하고 취소와 실패의 우선순위, 전체 검사 완료 여부, 인쇄 호출 횟수, 자원 정리를 확인한다.

근거: DESIGN 3·4·11절. 제어 흐름 검사에 사용하는 시험 대역은 실제 SDK·장치 동작 증거를 대체하지 않는다.

## TASK-07: 공통 DLL 인수 검증 및 배포 검증

목적: UI 구현 전에 공통 DLL의 계약과 독립 사용 가능 여부를 확인한다.

완료 조건:

- [ ] C01~C24 각각에 실행한 검사·기대/실제 결과·구현 커밋을 연결한다. 실패 및 미실행을 통과로 집계하지 않는다.
- [ ] 실제 USB 장치로 단건·일괄·한글·한 행 한 장·RFID 보존·오류·취소·timeout·해제 후 재연결을 확인한다.
- [ ] x86/x64에서 기준 native 한 쌍의 배포·로드·ABI를 확인하고 누락·비트 수·해시·기존 모듈 충돌·export 오류를 구분한다.
- [ ] TCP/IP·RS-232는 API 구현·자동 검사·실기를 구분한 지원 표를 작성한다. 장치 미확보로 실기하지 못한 경로는 미검증으로 남기며 출력 지원 확인을 주장하지 않는다.
- [ ] 독립 최소 호출 프로그램에서 DevExpress·DB 없이 관리 검사와 DLL 호출이 가능함을 확인한다.
- [ ] DLL 사용 예시·native 파일 배치·오류와 배포 방법을 문서화하고 남은 장치 제한을 명시한다.
- [ ] USB 1차 완료 조건에 해당하는 모든 필수 검사와 C01~C24 계약을 충족한 뒤 Tester 작업을 시작한다.

근거: DESIGN 5·7·8·11절. 제조사 바이너리와 실제 데이터는 시험 결과 문서에 업로드하지 않는다.

## TASK-08: DevExpress WinForms Tester 구현

목적: 완성된 DLL의 서식 편집·검사·출력을 DB 없이 사용하고 확인한다.

완료 조건:

- [ ] .NET Framework 4.6.1, WinForms, DevExpress 20.2.6으로 구성하고 x86/x64 출력 폴더를 분리한다.
- [ ] BTPL·JSON 불러오기/저장, 텍스트 추가·삭제·복사·수치 편집, 변수 매핑과 합성 DataTable 편집을 제공한다.
