# 동기 인쇄의 선택 배출·복귀

현재 계약은 [이슈 #16 스펙](specs/SYNC_USB_MVP.md)과 [공개 API](PRINTER_API.ko.md)다. 이전 #13 worker/일괄/취소 계약과 검증 기록은 [역사 문서](history/PRINT_PRESENTATION_issue13.md)에 보존한다.

```csharp
using (var printer = new Bt003Printer())
{
    // 15는 운영 기준 용지의 확인값이며 다른 용지는 보정 절차로 정한다. 기본값은 0이다.
    var connected = printer.ConnectUsb(selectedUsbPort, 15);
    if (!connected.IsSuccess) return;
    var result = printer.PrintFile(formPath);
    // bool로 정상 여부를 판단하고 Message로 이유를 읽는다. PrintCode는 인쇄 응답을 보존한다.
    if (!result.IsSuccess) Console.WriteLine(result.Message);
    // 실패·불명 또는 정상 인쇄 뒤 배출 실패에 자동 재출력하지 않는다.
}
```

배출 거리는 ConnectUsb의 0..1000 mm 인수다. 정상 응답을 받은 한 장 인쇄 뒤에만 ^M을 보내고, 다음 인쇄 전에 이전 정상 배출 거리를 ^B로 복귀한다. 이전 15·새 설정 7이면 B15 → 인쇄 → M7이다. 새 설정 0이면 이전 거리는 복귀하되 추가 전진하지 않는다. 연결 해제 자체는 용지를 움직이지 않는다.

이동 진입 전에 포트별 위치를 불명으로 둔다. 반환 0에서만 명령 이력 거리를 기록한다. 비0·예외나 인쇄 불명 뒤에는 배출 설정 0이어도 다음 자동 인쇄를 IsSuccess=false로 차단하고 Message에 수동 정렬 필요를 설명한다. 재연결·새 객체가 위치 기록을 지우지 않는다. 주 작업의 마지막 이동 응답은 NativeCode이며 응답 전 예외는 null이다. Message는 복귀 또는 배출 실패를 구분하여 설명하고 PrintCode=0은 후속 이동·정리 실패에도 보존된다.

SDK 응답과 명령 이력은 물리 인쇄·이동 완료나 센서 위치 확인이 아니다. 사용자가 실제 용지를 인쇄 기준 위치로 정렬한 뒤 ConfirmPrintPosition을 호출하거나, FeedAndConfirmPosition으로 FEED와 확인을 함께 해야 한다. 연결 정리 오류는 Disconnect의 Closed 확인 후 재연결해야 복구된다. 수동 확인을 오류 무시 수단으로 자동 호출하지 않는다.

포트별 기록은 프로세스 메모리와 `C:\Bitek\BT003\position.txt`에 함께 둔다. 프로그램을 다시 실행하면 파일 기록으로 직전 배출 거리를 복귀한다. 파일이 없는 최초 실행이나 손상·다른 포트·중단된 기록은 위치 불명이며, 운영자가 정렬한 뒤 ConfirmPrintPosition(또는 FeedAndConfirmPosition)을 호출하면 파일이 0으로 생성된다. 다른 프로그램의 사용, 장치 교체, 수동 FEED/당김과 용지 교체는 자동 감지하지 않는다. LCD 정지 위치는 잠금 중에도 바뀐 관측이 있어 운영 기준으로 쓰지 않는다. 서식의 E 설정은 SDK 서식 설정이며 DLL의 배출 완료 보장이 아니다. 배출을 위해 템플릿에 M/B를 추가하지 않는다.

## 운영 기준

2026-10-14 x64·x86 실기로 확인했다. 용지는 받침지 70×35 mm와 블랙마크 5 mm(피치 40 mm), 흰 라벨 60×20 mm이며 반사 센서로 감지한다. 해상도는 300dpi(약 11.81 dot/mm)다.

운영 표준은 **`^Q35,5,9+`와 `ConnectUsb(port, 15)`**이다. 이 조합은 FEED 직후, 직전 인쇄 정지 그대로, M/B 복귀 뒤, 프로그램 재실행 뒤 모두 같은 위치(±0.35~0.6 mm)로 인쇄됐고 인쇄 후 블랙마크가 출구 끝에 멈췄다. 서식 원점은 흰 라벨 상단이 아니라 그보다 약 3.6 mm 위다. 흰 라벨은 서식 좌표 약 X 47~741, Y 42~279다.

- `^Qx,y,z±`의 x는 마크를 뺀 라벨 길이(35), y는 마크 폭(5), z는 마크에서 서식 상단까지 거리다(제조사 매뉴얼 10쪽 그림 2). x에 피치 40을 넣으면 프린터가 피치를 45 mm로 알고, 마크를 다시 맞출 때 라벨 중간에서 멈췄다가 빈 라벨을 한 장 더 낸다.
- z=12.5(마크 5 + 흰 부분 7.5)는 원점이 라벨 상단에 오지만 불안정했다. FEED 직후 첫 장이 약 20 mm 앞서 인쇄됐고, 연속 셋째 장부터 약 3 mm 밀린 위치로 굳었다. 마크 경계와 맞물리는 z로 보이며 쓰지 않는다.
- `^Q` 두 인수는 Gap 형식이며 프린터 LCD의 라벨 유형까지 간격 라벨로 바꾼다. TXT 편집기는 두 인수 `^Q`를 만들거나 저장하지 않는다.
- Q 값을 바꾸면 바꾼 뒤 첫 장은 이전 원점으로 인쇄된다. 바꾼 Q로 한 장 인쇄한 뒤 FEED로 다시 맞추고 사용한다. FEED·M/B로 생긴 어긋남은 다시 FEED할 때까지 남는다.
- 프린터는 인쇄 후 다음 라벨의 서식 상단이 헤드에 오는 위치에서 멈춘다. z로 원점을 내리면 같은 거리만큼 덜 나오므로 추가 배출 거리로 맞춘다.
- 앞 장의 인쇄·배출이 끝나기 전에 다음 장을 보내면 프린터가 멈칫하고 위치가 밀릴 수 있어, DLL은 직전 SDK 이동 뒤 2초가 지나지 않았으면 기다린 뒤 인쇄한다.
- `AW`의 X=0은 SDK 인쇄 예외를 냈다(X=1부터 정상). 편집기는 X를 1 이상으로 제한한다.
- LCD 메뉴가 열린 상태에서 인쇄하면 SDK가 101을 반환하고 메뉴를 닫을 때 용지가 움직일 수 있다. DLL은 위치를 불명으로 기록하므로 대기 화면에서 FEED 후 ConfirmPrintPosition을 호출한다(또는 대기 화면에서 FeedAndConfirmPosition).
- FEED 키를 누른 뒤 ConfirmPrintPosition을 호출하지 않으면 DLL이 배출 상태로 알고 복귀해 다음 장이 배출 거리만큼 밀린다. FeedAndConfirmPosition은 FEED와 확인을 한 호출로 묶어 이 누락을 막는다. 배출 상태에서도 복귀 없이 FEED만 보내며, 이는 실기로 확인한 수동 절차와 같다. `~S,FEED` 전송 경로는 아직 실기로 확인하지 않았다(물리 FEED 키 + ConfirmPrintPosition 절차만 확인).
- 문구·바코드는 SafeArea(X 71~732, Y 66~255 dot, 10호 글자는 시작 Y를 약 225 이하로) 안에 배치한다. 범위 밖은 받침지라 흐리게 찍히거나 보이지 않는다.

### 다른 라벨 크기의 인쇄 영역과 보정

`BtplBlackMarkMedia`가 자로 잰 값과 실측 보정으로 Q·W와 영역을 계산한다. 미리보기 표시는 호출 프로그램이 맡는다.

| 경계 | 계산 (mm × dpi ÷ 25.4) | 운영 기준 용지 | 실측 |
|---|---|---|---|
| 왼쪽 X | (받침지 폭 − 라벨 폭) ÷ 2 + 가로 보정(−1.0) | 47 | 약 47 |
| 오른쪽 X | 왼쪽 + 라벨 폭 | 756 | 약 741 |
| 위 Y | 세로 보정(3.6) | 43 | 약 42 |
| 아래 Y | 위 + 라벨 높이 | 279 | 약 279 |

오른쪽 차이(약 1.3 mm)는 라벨 폭 측정 오차로 보이며 2 mm 안쪽 SafeArea가 흡수한다. 글자 높이는 SDK 글꼴에 따르므로 실제 출력으로 확인한다.

새 용지는 x(마크를 뺀 길이)와 y(마크 폭)를 자로 재어 정한다. z는 받침지에 마크가 인쇄된 위치로 정해지므로 x·y로 계산할 수 없고, 두 인수 ^Q는 Gap 형식이라 z가 없다. 이 프린터에서는 자로 잰 흰 부분 + 1.5 mm(운영 기준 용지 z=9)가 안정적이었다.

1. 새 Q로 한 장 인쇄한 뒤 대기 화면에서 FEED하고 ConfirmPrintPosition을 호출한다(또는 FeedAndConfirmPosition).
2. Y000부터 10 dot 간격 눈금선(`Lo`)을 둔 서식으로 같은 프로세스에서 배출 0 세 장, 배출 거리 세 장을 인쇄하고 재실행해 한 장 더 인쇄한다. 모두 같은 위치여야 그 z를 쓴다.
3. 라벨 상단·왼쪽 끝이 걸린 눈금으로 세로·가로 보정값을 정하고, 인쇄 후 마크 위치를 보고 배출 거리를 정한다.

```csharp
// 자로 잰 값: 받침지 폭, 마크 제외 길이, 마크 폭, 흰 부분, 흰 라벨 폭·높이(mm). 300dpi와 이 프린터 실측 보정이 기본값이다.
var media = new BtplBlackMarkMedia(70, 35, 5, 7.5m, 60, 20);
template = template.WithSetting(media.LabelSetting).WithSetting(media.WidthSetting); // ^Q35,5,9+ / ^W70
BtplArea safe = media.SafeArea; // X 71~732, Y 66~255 dot
```

기존 `^Q40,5,7.5+` 서식(원점이 흰 라벨 상단보다 약 5.8 mm 위)을 표준으로 옮길 때는 Q 줄을 `^Q35,5,9+`로 바꾸고 모든 `AW`·`AC`의 Y에서 26 dot를 빼면 이전과 같은 위치에 인쇄된다(예: Y120 → Y094).

### 다시 실기하는 경우

위 기준은 이 프린터 한 대, 이 용지 한 종, 현재 인쇄 경로 코드로 확인했다. 아래 경우에만 다시 실기한다.

- 용지 규격이 바뀌면 위 보정 절차(1~3)를 그 용지로 한 번 한다. 센서 보정 1.5 mm와 세로 3.6 mm·가로 −1.0 mm 보정은 이 용지에서만 쟀다.
- 프린터 본체·펌웨어가 바뀌거나 203dpi 기종이면 같은 보정 절차를 한다.
- `Bt003Printer`의 인쇄·배출·복귀·위치 기록·간격 코드를 고치면 짧은 회귀 실기를 한다. 재실행 첫 장, 같은 프로세스 연속 3장, FEED 후 확인 뒤 한 장을 인쇄해 모두 라벨 상단 Y≈042이고 마크가 출구 끝에 멈추는지 본다.
- 제조사 SDK DLL은 고정 해시라 바뀌면 verify-build가 실패한다. 새 SDK를 채택할 때는 위 회귀 실기도 함께 한다.

여러 장은 Print/PrintFile을 반복 호출해 인쇄하며 장마다 2초 간격이 생긴다. 대량 일괄 인쇄 API나 용도는 없다. 용지·리본·헤드 오류와 인쇄 중 USB 분리는 이 저장소의 검증 범위가 아니다.

관리 Link harness가 복귀/배출 실패·예외, 마지막 이동 응답, 위치 불명과 재연결, 수동 확인, 해제 실패 뒤 재사용 차단을 확인한다. 실제 물리 출력·반복 정렬·배출은 [별도 실기](history/HARDWARE_VALIDATION.ko.md)에서 확인해야 한다.
