# Tester 사용과 용지 운영

- [Tester 사용](#tester-사용): 실행·설정·편집·저장·인쇄·중단
- [공통 복구](#공통-복구): 용지 위치 불명과 연결 오류
- [운영 기준](#운영-기준): 확인한 용지·서식·배출·보정 및 새 용지 확인 절차
- [전원 재투입 후 알려진 제한](#전원-재투입-후-알려진-제한): 첫 장 위치·FEED 관측과 자동 복원 한계
- [실측 보정과 미리보기의 한계](#실측-보정과-미리보기의-한계): 기본값과 개별 보정, 실제 잘림과 표시 차이

## Tester 사용

### 실행과 설정

1. 같은 비트수의 배포 폴더에서 `U2BIO.BT003PROLabelPrinting.Tester.exe`를 실행한다. 한 번에 하나만 실행되며 x86/x64는 같은 사용자 설정을 쓴다.
2. [설정]의 **연결** 탭에서 감지된 USB 프린터와 배출 거리를 선택한다. 감지되지 않으면 [다시 감지]하고 연결 상태를 확인한다. 실제 포트 대응은 프린터 한 대·포트 0에서 확인했다.
3. **프린터 보정** 탭에서 장착 용지 방식, dpi, 센서·세로·가로 보정을 확인한다. 보정값은 아래 운영·실측 절을 참고한다. 연결 중 포트·배출 설정을 바꾸면 다음 연결에 적용되므로 [해제] 후 다시 연결한다.
4. [확인(F12)]으로 저장하거나 [취소(ESC)]한다. 설정은 사용자 로컬 앱 데이터의 `U2BIO/BT003Tester/settings.xml`에 저장된다. 서식 탭·서식 폴더 설정은 없으며 이전 XML의 나머지 설정은 유지한다.

### 열기·편집·저장

1. [열기]로 기존 TXT를 선택한다. 열기▼에는 최근 파일과 [서식 닫기]가 있다. 시작 폴더는 현재 서식 폴더 → 최근 목록에서 존재하는 파일의 폴더 → Windows 기본 위치 순이다. 새 서식 만들기는 제공하지 않으므로 기존 TXT를 [다른 이름 저장]해 시작한다.
2. 왼쪽 AW 목록에서 X·Y·크기·굵기·문구를 수정하거나 문구를 추가·삭제한다. 오류가 표시된 칸은 고치거나 ESC로 취소한다. X는 1 이상이어야 한다. 오른쪽 **원문**은 읽기 전용 확인 화면이다.
3. **용지·인쇄**에서 실측 칸과 `^Q`·`^W`, 속도·농도를 확인한다. 연결된 실측 칸을 바꾸면 받침지 너비는 `^W`, 마크 관련 값은 `^Q`에 반영된다. 라벨 너비·길이와 dpi·위치 보정은 미리보기 영역용이며 TXT에 저장되지 않는다. 설정 변경만으로 열린 서식의 `^Q`·`^W`가 바뀌지는 않는다. 상태가 반영 불가를 안내하면 해당 서식 명령을 확인하며, 프로그램은 누락·간격 형식을 임의로 고치지 않는다.
4. [되돌리기]는 직전 원문 편집을 취소한다. 되돌리기▼에서 [다시 실행(Ctrl+Y)], [마지막 저장 상태로], [처음 연 상태로]를 선택한다. 용지 치수·보정·가변데이터는 원문 편집 기록에 포함되지 않는다.
5. [저장]은 현재 파일, 저장▼의 [다른 이름 저장]은 새 TXT에 저장한다. 성공하면 새 경로가 이후 저장 기준이 된다. 외부에서 파일이 바뀌면 다시 읽기·다른 이름 저장·편집 유지 중 선택하며 저장 실패는 편집 내용을 버리지 않는다.
6. 파일 전환·서식 닫기·종료 때 미저장 변경이 있으면 저장 여부를 확인한다. 취소하거나 저장이 실패하면 전환·종료를 멈춘다.

미리보기 실선은 계산한 라벨 영역, 점선은 안전 영역이다. 선택한 줄의 기준선·잉크 범위와 경고를 확인한다. **라벨 밖 문구도 진단용으로 계속 표시하므로 실제로 잘린 글자 모양을 재현하지 않는다.** 미지원 줄·정렬·회전·글꼴/자동 줄바꿈 미반영과 판정 불가 경고를 실제 출력 보장으로 해석하지 않는다.

### 연결·인쇄·중단

1. 다른 프로그램이 같은 프린터를 사용하지 않는지 확인하고 [연결]한다. 연결▼의 [연결 상태 조회]는 SDK 연결 상태만 조회하며 용지 위치나 실제 출력 완료를 확인하지 않는다.
2. 신뢰할 위치 기록이 없거나 실제 위치가 불명확하면 아래 [공통 복구](#공통-복구)에 따라 프린터 대기 화면에서 [FEED+확인]을 누른다. 이 버튼은 실제 용지를 이송하며 수동 위치 확인 메뉴는 제공하지 않는다. 전원이 유지되고 실제 용지 위치와 유효한 기록이 일치하면 앱 재실행 후에도 매번 FEED할 필요는 없다. 프린터 전원을 껐다 켠 경우에는 [전원 재투입 후 알려진 제한](#전원-재투입-후-알려진-제한)을 확인한다.
3. 변수 서식이면 **가변데이터**에 `!!`로 구분한 원문 값을 V00부터 필요한 번호까지 매번 입력한다. 빈 칸은 변수 등록을 생략하므로 변수 없는 서식에서만 사용한다. 입력값의 빈 항목·공백을 임의로 정리하지 않는다.
4. **요청 장수**를 정수 1~20으로 지정한다. 기본값은 1이며 재시작하면 1로 시작한다. 같은 원문·가변데이터를 한 장 API로 순차 요청하며 서식 수량 명령이나 SDK copies를 바꾸지 않는다.
5. [편집 중 서식 인쇄]는 현재 편집본, [저장된 파일 인쇄]는 디스크 파일을 사용한다. 미저장 수정은 파일 인쇄에 반영되지 않는다. 파일 인쇄는 확인한 원문과 매 장 인쇄 전 파일이 같아야 하며 변경되면 중단한다.
6. AW X 오류가 있으면 인쇄가 차단된다. 서식의 라벨 방식이 설정 용지와 다르거나 정할 수 없으면 확인창을 읽고 판단한다. 잉크 경고는 진단 표시이며 그 자체로 인쇄를 차단하지 않는다.
7. 반복 중에는 편집·설정·장치와 해당 메뉴가 잠긴다. [반복 중단]은 현재 SDK 호출이 돌아온 뒤 다음 장부터 중단하며 강제 취소가 아니다. 실패·불명·예외에서도 다음 요청을 멈추고 자동 재인쇄하지 않는다.
8. 결과 표의 장별 i/N, 성공 여부와 Message, 종료 요약의 요청·SDK 정상·실패/불명·미실행 수를 확인한다. **SDK 정상 수는 실제 출력 완료 장수가 아니다.**
9. 사용을 마치면 [해제]하거나 창을 닫는다. 작업 중 닫기는 현재 호출 반환을 기다리고 다음 요청을 중단한다. 미저장 취소·저장 실패는 종료를 멈추며, 연결 해제 결과와 정리 예외는 별도로 확인한다.

상태 줄의 **마지막 정렬 요청**은 이 연결에서 요청한 FEED+확인의 처리 결과·SDK 응답·시각이다. 실제 위치를 감지한 결과나 다음 인쇄 가능 판정이 아니다. 시작 시와 연결·해제 요청 후에는 없음으로 초기화하고, 인쇄·연결 상태 조회는 이 표시를 갱신하지 않는다. 이전 결과는 결과 표에서 확인한다. 처리 실패에는 SDK 호출 전 거부나 응답 0 뒤 기록 저장 실패도 포함되므로 Message를 함께 읽는다.

이 사용법은 현재 소스의 장수·메뉴 구성을 설명하며, 사용 중인 배포 버전이 같은 기능을 포함하는지는 배포 revision으로 확인한다. 실제 업무 프로그램의 통합·운영 검증은 이 사용 안내의 확인 범위에 포함되지 않는다.

## 공통 복구

Tester는 실제 FEED와 기록 갱신을 함께 하는 [FEED+확인]만 제공한다. DLL 호출 프로그램은 실제 수동 정렬 후 ConfirmPrintPosition을 호출하는 절차도 사용할 수 있다. 결과 설명은 사람이 확인하며 `Message` 문장을 프로그램이 파싱해 자동 복구하지 않는다.

아래 절차는 전원 유지 상태에서 확인한 운영 기준이다. 전원 재투입 후에는 첫 장 상단 이상과 FEED 안쪽 이동이 보고됐으며, [FEED+확인]이나 물리 FEED를 검증된 해결책으로 안내하지 않는다. SDK 정상 응답이나 위치 기록 0만으로 실제 정렬을 판단하지 말고 용지와 출력 결과를 확인한다.

| 상황 | 확인·복구 절차 |
| --- | --- |
| 용지 위치 불명, 첫 실행에 신뢰할 기록 없음 | Tester는 프린터 대기 화면에서 [FEED+확인]. DLL 호출자는 `FeedAndConfirmPosition` 또는 실제 수동 정렬 후 `ConfirmPrintPosition`. 후자는 용지를 움직이거나 센서를 조회하지 않는다. |
| 수동 FEED·용지 교체·당김 이후 | DLL이 자동 감지하지 못한다. Tester는 대기 화면에서 [FEED+확인]으로 다시 이송·기록한다. DLL 호출자는 실제 수동 정렬 뒤 `ConfirmPrintPosition`을 호출할 수 있다. 재연결로 기록을 초기화하지 않는다. |
| SDK 연결·해제·서식 정리 오류 | `Disconnect`([해제])의 Closed 확인 뒤 재연결한다. 위치 확인으로 연결 오류를 해제하지 않는다. 위치도 불명확하면 연결 복구 뒤 별도로 정렬한다. |
| 인쇄·배출·정리 실패 또는 결과 불명 | 이미 일부 출력됐을 수 있으므로 자동 재인쇄하지 않는다. 결과와 실제 용지를 확인한 뒤 후속 인쇄 여부를 사람이 결정한다. |

FEED는 실제 용지를 이송한다. LCD 메뉴를 닫고 대기 화면에서 사용하며, `^Q`를 바꿨다면 새 서식으로 한 장 인쇄한 뒤 Tester에서는 [FEED+확인]으로 다시 정렬한다. 물리 FEED를 이미 눌렀어도 Tester의 [FEED+확인]은 용지를 추가 이송한다. 기록만 0으로 만드는 수동 확인은 이전 배출 거리의 복귀를 생략시킬 수 있어 Tester에서 제공하지 않는다. 이미 지워진 이력은 재시작으로 복원되지 않는다. 이 절차의 물리 확인 범위는 아래 운영 용지와 명시된 관측 조건에 한정된다. 현재 Tester 메뉴 구성에서 빈 라벨 해소 여부는 물리 관측으로 확인하지 않았다. 다른 용지나 전원 재투입 후의 빈 라벨 해소도 보장하지 않는다.

## DLL의 배출·위치 기록

현재 인쇄·위치·정리 계약은 [공개 API](PRINTER_API_V2.ko.md)를 따른다. DLL은 동기 한 장 호출을 제공하며, 여러 장 반복과 중단 정책은 호출 프로그램이 관리한다.

```csharp
using (var printer = new Bt003Printer())
{
    // 15는 운영 기준 용지의 확인값이며 다른 용지는 보정 절차로 정한다. 기본값은 0이다.
    var connected = printer.ConnectUsb(selectedUsbPort, 15);
    if (!connected.IsSuccess) return;
    var result = printer.PrintFile(formPath);
    // bool로 정상 여부를 판단하고 Message로 이유를 읽는다. PrintCode는 인쇄 응답을 보존한다.
    if (!result.IsSuccess) Console.WriteLine(result.Message);
    // 실패·불명 또는 정상 인쇄 뒤 배출 실패에 자동 재출력하지 않는다.
}
```

배출 거리는 ConnectUsb의 0..1000 mm 인수다. 정상 응답을 받은 한 장 인쇄 뒤에만 ^M을 보내고, 다음 인쇄 전에 이전 정상 배출 거리를 ^B로 복귀한다. 이전 15·새 설정 7이면 B15 → 인쇄 → M7이다. 새 설정 0이면 이전 거리는 복귀하되 추가 전진하지 않는다. 연결 해제 자체는 용지를 움직이지 않는다.

이동 진입 전에 포트별 위치를 불명으로 둔다. 반환 0에서만 명령 이력 거리를 기록한다. 비0·예외나 인쇄 불명 뒤에는 배출 설정 0이어도 다음 자동 인쇄를 IsSuccess=false로 차단하고 Message에 수동 정렬 필요를 설명한다. 재연결·새 객체가 위치 기록을 지우지 않는다. 주 작업의 마지막 이동 응답은 NativeCode이며 응답 전 예외는 null이다. Message는 복귀 또는 배출 실패를 구분하여 설명하고 PrintCode=0은 후속 이동·정리 실패에도 보존된다.

SDK 응답과 명령 이력은 물리 인쇄·이동 완료나 센서 위치 확인이 아니다. DLL 호출 프로그램은 사용자가 실제 용지를 인쇄 기준 위치로 정렬한 뒤 ConfirmPrintPosition을 호출하거나, FeedAndConfirmPosition으로 FEED와 기록 갱신을 함께 한다. Tester에서는 [FEED+확인]을 사용한다. 연결 정리 오류는 Disconnect의 Closed 확인 후 재연결해야 복구된다. 수동 확인을 오류 무시 수단으로 자동 호출하지 않는다.

포트별 기록은 프로세스 메모리와 `C:\Bitek\BT003\position.txt`에 함께 둔다. 프로그램을 다시 실행하면 파일 기록으로 직전 배출 거리를 복귀한다. 파일이 없는 최초 실행이나 손상·다른 포트·중단된 기록은 위치 불명이며, DLL 호출자가 실제 수동 정렬 뒤 ConfirmPrintPosition을 호출하거나 FeedAndConfirmPosition을 호출하면 파일이 0으로 생성된다. Tester는 [FEED+확인]을 사용하며 이 파일을 직접 읽거나 쓰지 않는다. 다른 프로그램의 사용, 장치 교체, 수동 FEED/당김과 용지 교체는 자동 감지하지 않는다. LCD 정지 위치는 잠금 중에도 바뀐 관측이 있어 운영 기준으로 쓰지 않는다. 서식의 E 설정은 SDK 서식 설정이며 DLL의 배출 완료 보장이 아니다. 배출을 위해 템플릿에 M/B를 추가하지 않는다.

## 운영 기준

운영 용지에서 x64·x86 실기로 확인한 범위다. 용지는 받침지 70×35 mm와 블랙마크 5 mm(피치 40 mm), 흰 라벨 60×20 mm이며 반사 센서로 감지한다. 해상도는 300dpi(약 11.81 dot/mm)다.

운영 표준은 **`^Q35,5,9+`와 `ConnectUsb(port, 15)`**이다. 이 조합은 FEED 직후, 직전 인쇄 정지 그대로, M/B 복귀 뒤, 프로그램 재실행 뒤 모두 같은 위치(±0.35~0.6 mm)로 인쇄됐고 인쇄 후 블랙마크가 출구 끝에 멈췄다. 서식 원점은 흰 라벨 상단이 아니라 그보다 약 3.6 mm 위다. 흰 라벨은 서식 좌표 약 X 47~741, Y 42~279다.

이 결과는 전원 유지 상태의 운영 기록이며, 프린터 전원 재투입 뒤 첫 출력까지 보장하지 않는다. 앱 재실행과 프린터 전원 재투입은 다른 조건이다. 전원 재투입 후에는 아래 알려진 제한이 남아 있다.

- `^Qx,y,z±`의 x는 마크를 뺀 라벨 길이(35), y는 마크 폭(5), z는 마크에서 서식 상단까지 거리다(제조사 매뉴얼 10쪽 그림 2). x에 피치 40을 넣으면 프린터가 피치를 45 mm로 알고, 마크를 다시 맞출 때 라벨 중간에서 멈췄다가 빈 라벨을 한 장 더 낸다.
- z=12.5(마크 5 + 흰 부분 7.5)는 원점이 라벨 상단에 오지만 불안정했다. FEED 직후 첫 장이 약 20 mm 앞서 인쇄됐고, 연속 셋째 장부터 약 3 mm 밀린 위치로 굳었다. 마크 경계와 맞물리는 z로 보이며 쓰지 않는다.
- `^Q` 두 인수는 Gap 형식이며 프린터 LCD의 라벨 유형까지 간격 라벨로 바꾼다. TXT 편집기는 두 인수 `^Q`를 만들거나 저장하지 않는다. 인쇄 전에는 `BtplTemplate.LabelMode`로 서식 방식을 판정하고, Tester는 설정한 용지 방식과 다르거나 정할 수 없으면(`^Q` 없음·여러 줄·해석 불가) 확인을 받는다. DLL의 Print/PrintFile은 막지 않는다.
- Q 값을 바꾸면 바꾼 뒤 첫 장은 이전 원점으로 인쇄된다. 바꾼 Q로 한 장 인쇄한 뒤 FEED로 다시 맞추고 사용한다. FEED·M/B로 생긴 어긋남은 다시 FEED할 때까지 남는다.
- 프린터는 인쇄 후 다음 라벨의 서식 상단이 헤드에 오는 위치에서 멈춘다. z로 원점을 내리면 같은 거리만큼 덜 나오므로 추가 배출 거리로 맞춘다.
- 앞 장의 인쇄·배출이 끝나기 전에 다음 장을 보내면 프린터가 멈칫하고 위치가 밀릴 수 있어, DLL은 직전 SDK 이동 뒤 2초가 지나지 않았으면 기다린 뒤 인쇄한다.
- `AW`의 X=0은 SDK 인쇄 예외를 냈다(X=1부터 정상). 편집기는 X를 1 이상으로 제한한다.
- LCD 메뉴가 열린 상태에서 인쇄하면 SDK가 101을 반환하고 메뉴를 닫을 때 용지가 움직일 수 있다. DLL은 위치를 불명으로 기록하므로 대기 화면에서 FEED 후 ConfirmPrintPosition을 호출한다(또는 대기 화면에서 FeedAndConfirmPosition).
- FEED 키를 누른 뒤 ConfirmPrintPosition을 호출하지 않으면 DLL이 배출 상태로 알고 복귀해 다음 장이 배출 거리만큼 밀린다. 운영 기준 용지에서는 대기 화면에서 FeedAndConfirmPosition으로 FEED와 확인을 함께 한다. 수동 FEED 키를 쓴 경우에는 ConfirmPrintPosition을 반드시 호출한다. 배출 상태에서도 헬퍼는 복귀 없이 FEED만 보낸다.
- 문구·바코드는 SafeArea(X 71~732, Y 66~255 dot) 안에 배치한다. 범위 밖은 받침지라 흐리게 찍히거나 보이지 않는다. AW의 Y는 글자가 아니라 글자 셀의 위쪽 끝이다. SDK는 AW를 글꼴 설정(기본 돋움체)과 LOGFONT 셀 높이 `size × 340 ÷ 72`(10호 47 dot)로 그려 좌상단을 (X, Y)에 둔다. 예: 이 PC 돋움체 10호 "Not Used"의 잉크는 Y+6 ~ Y+40(반열림)이라 안전 영역 안에 두는 마지막 시작 Y는 215, 라벨 안은 239다. 한글·하강부(g·j·p) 문구는 잉크가 더 크다(예: "CK000001 홍길동 98-03-21" Y+3 ~ Y+44, "gjpqy" Y+6 ~ Y+47). 수치는 문자열·크기·굵기·글꼴마다 다르므로 Tester 미리보기의 잉크 경고로 확인하고, 물리 경계 오차가 있으므로 경계 근처는 실제 출력으로 확인한다.

운영 용지에서 x64·x86 Tester의 FEED 헬퍼 후 출력이 물리 FEED·확인 절차와 같은 위치였고, 반복·새 프로세스의 위치 불명 복구 뒤에도 불필요한 빈 라벨이나 멈칫 없는 출력이라는 사용자 관측이 있다. 인쇄 뒤 블랙마크가 출구 끝에 멈춘 것도 눈으로 확인했다. 이송 시간은 정밀 계측하지 않았고 SDK 응답 0만으로 매번 물리 정렬 완료를 보장하지 않는다. 정상 해제 시 용지 무이동·닫힘·정상 종료를 확인했으나 실제 해제 실패를 유발한 장치 시험은 하지 않았다.

### 전원 재투입 후 알려진 제한

프린터 전원을 껐다 켠 뒤 첫 출력에서 상단 위치 이상이 재현됐다. 전원 재투입과 연결만으로는 용지가 움직이지 않았고, 전원 유지 상태의 후속 출력은 정상이었다. 입력 `^E`를 생략한 비교에서도 첫 장 이상이 재현돼 해결책으로 채택하지 않았다.

FEED의 사용자 관측은 전원 유지 상태에서는 전진만 하고, 전원 재투입 후에는 후진→전진→후진으로 위치를 잡는다는 것이다. [FEED+확인]과 물리 FEED 모두에서 전원 후 동작 차이가 보고됐다. 인쇄된 글자의 노출 차이만으로 동일 라벨의 이동량이나 블랙마크 기준 정지 오차를 계산하지 않는다.

현재 DLL의 FEED 경로는 `~S,FEED`만 보내며, B/M 복귀·추가 배출을 보내지 않는다. 앞뒤 이동만으로 센서 캘리브레이션이라고 확정할 수 없고, 전원 후 위치 재탐색·정렬이라는 설명도 가설이다. 원인과 정렬 복구 방법은 미확정이며, FEED가 항상 전진하거나 전원 전과 같은 위치로 복구한다고 보장하지 않는다. 개발자가 제어할 수 있는 범위는 [API의 위치 기록과 알려진 제한](PRINTER_API_V2.ko.md#위치-기록과-알려진-제한)을 참고한다.

현재 DLL은 전원 재투입을 자동 감지하거나 프린터 내부 원점을 저장·복원하지 않는다. 이전 배출 기록은 명령 이력이며 전원 재투입 후 실제 위치의 증거가 아니다. 기존 `B15 → P → M15`를 유지하고 자동 FEED·기록 강제 초기화·임의 거리 또는 좌표 보정을 추가하지 않았다. FEED를 전원 재투입 후 필수 절차나 확정된 해결책으로 보장하지 않으며, 실제 정렬을 확인하지 않은 채 기록만 0으로 바꾸지 않는다.

한 비교 조건에서는 전원 유지·재투입의 전체 B/P/M USB 전송이 같았는데 출력 위치가 달랐다. 이는 명령 전송과 실제 정렬을 구분해야 한다는 근거이며, 특정 내부 원인이나 영구적인 해결 불가능을 입증하지는 않는다. 현재 인터페이스로는 전원 후 자동 위치 복원을 보장할 수 없다.

### 다른 라벨 크기의 인쇄 영역과 보정

`BtplBlackMarkMedia`가 자로 잰 값과 실측 보정으로 Q·W와 영역을 계산한다. 미리보기 표시는 호출 프로그램이 맡는다.

| 경계 | 계산 (mm × dpi ÷ 25.4) | 운영 기준 용지 | 실측 |
|---|---|---|---|
| 왼쪽 X | (받침지 폭 − 라벨 폭) ÷ 2 + 가로 보정(−1.0) | 47 | 약 47 |
| 오른쪽 X | 왼쪽 + 라벨 폭 | 756 | 약 741 |
| 위 Y | 세로 보정(3.6) | 43 | 약 42 |
| 아래 Y | 위 + 라벨 높이 | 279 | 약 279 |

위 표는 기본 보정값과 과거 눈금 관측의 비교다. 사용자가 라벨 폭 60 mm와 좌우 여백 각각 5 mm를 실측 확인했으므로, 오른쪽 차이를 라벨 폭 측정 오차로 해석하지 않는다. SafeArea가 모든 물리 오차를 흡수한다고 보장하지 않는다. 다음 실측 보정과 글꼴별 잉크 경계를 함께 확인한다.

새 용지는 x(마크를 뺀 길이)와 y(마크 폭)를 자로 재어 정한다. z는 받침지에 마크가 인쇄된 위치로 정해지므로 x·y로 계산할 수 없고, 두 인수 ^Q는 Gap 형식이라 z가 없다. 이 프린터에서는 자로 잰 흰 부분 + 1.5 mm(운영 기준 용지 z=9)가 안정적이었다.

1. 새 Q로 한 장 인쇄한 뒤 대기 화면에서 Tester의 [FEED+확인] 또는 DLL의 FeedAndConfirmPosition을 호출한다. 외부 DLL 호출 프로그램은 실제 수동 FEED·정렬 뒤 ConfirmPrintPosition을 호출하는 절차도 사용할 수 있다.
2. Y000부터 10 dot 간격 눈금선(`Lo`)을 둔 서식으로 같은 프로세스에서 배출 0 세 장, 배출 거리 세 장을 인쇄하고 재실행해 한 장 더 인쇄한다. 모두 같은 위치여야 그 z를 쓴다.
3. 라벨 상단·왼쪽 끝이 걸린 눈금으로 세로·가로 보정값을 정하고, 인쇄 후 마크 위치를 보고 배출 거리를 정한다.

```csharp
// 자로 잰 값: 받침지 폭, 마크 제외 길이, 마크 폭, 흰 부분, 흰 라벨 폭·높이(mm). 300dpi와 이 프린터 실측 보정이 기본값이다.
var media = new BtplBlackMarkMedia(70, 35, 5, 7.5m, 60, 20);
template = template.WithSetting(media.LabelSetting).WithSetting(media.WidthSetting); // ^Q35,5,9+ / ^W70
BtplArea safe = media.SafeArea; // X 71~732, Y 66~255 dot
```

기존 `^Q40,5,7.5+` 서식(원점이 흰 라벨 상단보다 약 5.8 mm 위)을 표준으로 옮길 때는 Q 줄을 `^Q35,5,9+`로 바꾸고 모든 `AW`·`AC`의 Y에서 26 dot를 빼면 이전과 같은 위치에 인쇄된다(예: Y120 → Y094).

### 실측 보정과 미리보기의 한계

설정의 보정값 자체를 자동 측정하거나 찾아내는 기능은 없다. 실측해 입력한 값으로 DLL의 `BtplBlackMarkMedia`가 서식 설정과 표시 영역을 계산한다.

| 설정 | 계산에 쓰이는 의미 | 실제 인쇄·FEED에 대한 적용 범위 |
|---|---|---|
| 센서 보정 | 마크~라벨 간격에 더해 `^Q` 셋째 인수를 0.5 mm 단위로 반올림 | 계산한 `^Q`가 서식에 반영돼 인쇄되면 용지 위치 설정에 영향을 줄 수 있다. 센서 감도를 조절하는 값은 아니다. |
| 세로 보정 | 서식 Y0부터 흰 라벨 상단까지의 거리 | 미리보기의 LabelArea·SafeArea 계산용이며 인쇄 문구 Y를 이동하지 않는다. |
| 가로 보정 | 받침지 가운데 정렬 대비 라벨 왼쪽 끝의 이동량. +는 오른쪽, −는 왼쪽 | 미리보기의 LabelArea·SafeArea 계산용이며 인쇄 문구 X를 이동하지 않는다. |

설정 창에서 확인하는 것만으로 열린 서식의 `^Q`·`^W`는 바뀌지 않는다. 연결된 용지·인쇄 칸의 마크 치수를 편집하면 계산된 `^Q`를 편집본에 반영하며, 저장된 파일 인쇄에는 저장된 내용이 적용된다. 연결과 [FEED+확인]은 세 보정값을 별도로 전송하지 않는다. 이 값들은 전원 재투입 후 원점이나 이전 정지 기록을 복원하는 기능이 아니다.

운영 용지의 라벨은 60×20 mm, 받침지는 70 mm, 좌우 여백은 각각 5 mm다. Q·W·배출 거리는 변경하지 않았다. 편집 중 서식 인쇄와 저장 파일 인쇄는 각각 정상 응답 및 같은 출력 위치였고, 사용자는 불필요한 빈 라벨과 멈칫이 없음을 확인했다. 첫 글자 잉크의 라벨 왼쪽·위쪽 여백은 각각 **4 mm 실측값**이다.

이 PC의 돋움체 10호 첫 글자 잉크 시작점 X82/Y100 dot를 이용하면 가로 보정은 `82 × 25.4 / 300 − 4 − 5 = −2.057… mm`, 세로 보정은 `100 × 25.4 / 300 − 4 = 4.466… mm`다. 사용자가 Tester 설정에 가로 **−2.06 mm**, 세로 **4.47 mm**를 적용했다. 센서 보정 1.5 mm와 300dpi는 그대로다. 이때 반열림 LabelArea는 X35~743/Y53~289, SafeArea는 X58~720/Y76~265 dot다. 라이브러리와 Tester의 기본값(가로 −1.0/세로 3.6)은 변경하지 않았으며, 위 값은 이 PC·용지·글꼴에서 적용한 보정 후보다.

| 비교 | 사용자 관측 | 계산 및 한계 |
|---|---|---|
| 하단 근처 AW Y215 | 잉크 하단부터 라벨 끝까지 약 3 mm, 문구 온전 | 종전 약 2 mm와 차이 약 1 mm(약 12 dot). 보정 후 2.88 mm이며 근사 실측과 양립한다. |
| 하단 초과 AW Y260 | 문구 아래쪽 잘림 | 종전 미리보기 아래 21 dot 초과. 실제 잘림 양을 정밀 계측한 것은 아니다. |
| 한글 혼합 가변데이터 | 첫 줄 온전, 긴 둘째 줄은 끝에서 두 번째 한글의 왼쪽 획 일부만 보이고 마지막 글자는 보이지 않음. 받침지에는 글자 없음 | 종전 오른쪽 초과 65 dot, 보정 후 78 dot는 계산값이다. 실제 절단점의 정량 일치로 판정하지 않는다. |
| 첫 줄 잉크 전체 폭 | 30.0 mm 실측 | 렌더러 계산 29.972 mm. |
| 둘째 줄 첫 잉크 왼쪽 여백 | 14 mm 실측, 0.2 mm 판독 곤란 | 계산 14.224 mm. 관측값을 14.2 mm로 바꾸거나 정밀 일치로 보고하지 않는다. |

미리보기는 라벨 밖 문구를 빨간색으로 계속 그리는 **진단 표시**다. 실제 출력처럼 LabelArea 경계에서 글자 모양을 잘라 그리지 않으며 받침지 캔버스에서만 표시를 제한한다. 따라서 경고 발생과 실물의 잘린 글자 모양이 같다는 판정은 구분해야 한다. 이번 후속 조치는 실측 보정 및 이 표시 차이의 문서화이며, 실제 획 단위 절단점 일치·다른 글꼴/위치 일반화·실물처럼 잘라 보이는 표시 기능까지 검증하거나 구현하지 않았다.

정상 해제는 SDK 응답 0과 닫힘 확인 0, 사용자 용지 무이동 및 정상 종료를 확인했다. 실제 장치의 해제 실패를 유발한 시험은 하지 않았으며, 오류 알림의 관리형 검증과 구분한다.

### 다시 실기하는 경우

위 기준은 이 프린터 한 대, 이 용지 한 종, 현재 인쇄 경로 코드로 확인했다. 아래 경우에만 다시 실기한다.

- 용지 규격이 바뀌면 위 보정 절차(1~3)를 그 용지로 한 번 한다. 센서 보정 1.5 mm와 세로 3.6 mm·가로 −1.0 mm 보정은 이 용지에서만 쟀다.
- 프린터 본체·펌웨어가 바뀌거나 203dpi 기종이면 같은 보정 절차를 한다.
- `Bt003Printer`의 인쇄·배출·복귀·위치 기록·간격 코드를 고치면 짧은 회귀 실기를 한다. 재실행 첫 장, 같은 프로세스 연속 3장, Tester의 [FEED+확인](DLL은 FeedAndConfirmPosition) 후 한 장을 인쇄해 모두 사용하는 보정값의 기준 출력과 같은 위치이고 마크가 출구 끝에 멈추는지 본다.
- 제조사 SDK DLL은 고정 해시라 바뀌면 verify-build가 실패한다. 새 SDK를 채택할 때는 위 회귀 실기도 함께 한다.

여러 장은 Print/PrintFile을 반복 호출해 인쇄하며 장마다 2초 간격이 생긴다. 대량 일괄 인쇄 API나 용도는 없다. 용지·리본·헤드 오류와 인쇄 중 USB 분리는 이 저장소의 검증 범위가 아니다.

관리 Link harness가 복귀/배출 실패·예외, 마지막 이동 응답, 위치 불명과 재연결, 수동 확인, 해제 실패 뒤 재사용 차단을 확인한다. 관리 검증은 물리 출력·반복 정렬·배출의 증거가 아니며, 변경된 장치·용지·코드는 사용자 승인과 직접 관측으로 확인한다. 확인된 운영 조건과 물리 관측의 한계는 위 운영 기준과 실측 절에 정리되어 있다.
